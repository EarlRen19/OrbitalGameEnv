# OrbitalGameEnv

本项目是一个基于强化学习的卫星轨道追逃博弈仿真环境。它旨在模拟多智能体（追击方和逃逸方）在轨道空间中的对抗行为。

## 核心模块与关系

本项目的核心逻辑由几个关键的Python文件组成，它们共同定义了仿真环境、智能体模型和训练流程。下面将详细介绍这些文件及其相互关系。

### 文件概览

-   `env/mpe_env.py`: 定义了一个 **完全可观测** 的多智能体追逃环境 (`MPEEnv`)。
-   `env/mpe_pomdp_env.py`: 继承并修改 `MPEEnv`，定义了一个 **部分可观测** 的环境 (`MPE_POMDP_Env`)。
-   `demos/pe_env/train_pomdp.py`: 实现了核心的 **模型架构** 和 **训练逻辑**，用于在部分可观测环境下训练智能体。
-   `demos/pe_env/run_training.py`: **启动训练的入口脚本**，用于配置和运行 `train_pomdp.py` 中的训练流程。
-   `env/encoder.py`: 实现了一个基于注意力机制的观测编码器 (`AttentionBasedEncoder`)，作为模型的一部分。

### 详细介绍与关系

#### 1. 仿真环境

##### `env/mpe_env.py` (完全可观测环境 - MDP)

这是项目的基础环境，实现了一个完全可观测的马尔可夫决策过程（MDP）。在此环境中：
-   **完全信息**：所有追击方在任何时刻都能精确地知道逃逸方和其他追击方的完整状态（位置、速度）。
-   **观测空间**：追击方的观测直接包含所有智能体的真实状态。
-   **奖励机制**：设计了复杂的奖励函数，包括距离、队形、燃料消耗和过程优势等，以引导追击方学习协作。
-   **课程学习**：支持通过动态调整任务难度（如初始燃料、捕获距离、轨道偏心率）来加速模型收敛。

##### `env/mpe_pomdp_env.py` (部分可观测环境 - POMDP)

该文件继承自 `MPEEnv`，构建了一个更真实、更具挑战性的部分可观测环境（POMDP）。
-   **部分信息**：模拟现实场景，追击方无法连续获得逃逸方的精确状态。默认配置下，观测是 **间歇性的（每2步获得一次），且仅包含位置信息（速度被隐藏）**。
-   **历史缓冲区**: 为了让智能体能够推断被隐藏的信息（如速度和意图），该环境为每个追击方维护了一个关于逃逸方的历史观测缓冲区。
-   **数据准备**: 在每一步，它都会为智能体准备两类核心输入：
    1.  **当前观测**: 包括自身的绝对状态和队友的相对状态（均包含燃料信息）。
    2.  **历史观测**: 将逃逸方的历史位置信息处理成相对于追击方当前状态的序列，并附带一个掩码（Mask）来标记哪些是真实观测，哪些是填充的重复数据。这些数据将送入Transformer进行处理。

#### 2. AI 模型与训练流程

##### `demos/pe_env/train_pomdp.py` (核心模型与训练逻辑)

此文件是项目的核心，定义了智能体的神经网络结构和训练算法。它采用了一种先进的 **非对称Actor-Critic**（也称为 **学生-教师**）范式。

-   **整体架构**:
    -   **教师 (Critic)**: Critic网络扮演“教师”角色。它能够访问环境的 **全部真实状态（特权信息）**，因此可以对当前局势做出非常准确的价值判断。
    -   **学生 (Actor)**: Actor网络扮演“学生”角色。它只能看到 **部分可观测** 的信息（即 `mpe_pomdp_env.py` 提供的当前观测和历史序列），并负责做出实际决策。

-   **学生网络 (Actor) 的内部结构**:
    1.  **历史处理 (Transformer)**: 学生网络首先使用一个 **Transformer编码器** 来处理逃逸方的历史观测序列。这使其能够从不完整的时间序列数据中提取关于目标动态和意图的深度特征。
    2.  **信息融合 (`encoder.py`)**: 来自Transformer的特征，会与智能体自身的状态、队友的状态等当前信息，一同被送入 `AttentionBasedEncoder`。这个模块使用注意力机制来动态地权衡不同信息的重要性，最终融合成一个全面的状态表征。
    3.  **决策**: 基于这个融合后的状态表征，Actor网络最终输出决策动作。

-   **训练算法 (PPO + 知识蒸馏)**:
    -   **PPO**: 采用近端策略优化（PPO）算法来更新Actor和Critic网络，这是主要的强化学习驱动力。
    -   **知识蒸馏 (Distillation)**: 为了让“学生”能从“教师”那里学得更快更好，训练中加入了一个 **蒸馏损失**。该损失函数鼓励学生网络（Actor）产生的内部特征表示，去逼近教师网络（Critic）基于完全信息所产生的特征表示。这相当于教师在告诉学生：“虽然你信息不全，但一个好的决策者在看到你这些信息时，脑中想的应该是这样一幅画面”。

##### `demos/pe_env/run_training.py` (训练入口)

这是一个便捷的命令行工具，作为整个训练任务的入口。
-   **功能**: 解析命令行参数，覆盖 `MPE_POMDP_EnvCfg` 和 `TrainConfig` 中的默认设置。
-   **使用**: 用户可以通过该脚本轻松调整实验的各种超参数，如智能体数量、学习率、模型结构、奖励权重等，并启动训练。

## 如何运行

通过 `run_training.py` 脚本来启动训练。所有环境和训练的超参数都可以通过命令行进行配置。

### 示例

启动一个4追击者 vs 1逃逸者的POMDP训练，使用基于Transformer的智能体，并为该实验命名：

```bash
python OrbitalGameEnv/demos/pe_env/run_training.py \
    --num_p 4 \
    --num_e 1 \
    --use_partial_obs True \
    --obs_interval 2 \
    --history_len 20 \
    --use_encoder True \
    --total_timesteps 10000000 \
    --run_name "pomdp_4v1_transformer_distill"
```

### 关键参数说明

-   `--num_p`: 追击者数量。
-   `--use_partial_obs`: 是否启用部分可观测模式 (`True` 使用 `MPE_POMDP_Env`，`False` 使用 `MPEEnv`)。
-   `--obs_interval`: 在POMDP模式下，每隔多少步进行一次真实观测。
-   `--history_len`: Transformer处理的历史轨迹长度。
-   `--use_encoder`: 是否使用 `AttentionBasedEncoder` 进行信息融合。
-   `--run_name`: 为本次实验指定的名称，用于TensorBoard日志和模型保存。
-   `--resume_from_checkpoint`: 从指定的检查点文件路径恢复训练。
-   `--debug_observation`: 打印详细的观测信息以供调试。
